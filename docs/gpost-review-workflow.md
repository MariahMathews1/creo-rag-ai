# G-POST review workflow

1. Select a machine and an eligible draft/approved profile revision.
2. Select only the machine documents, approved reference programs, and approved standard needed for context.
3. Create the R&D draft and inspect capability unknowns or family conflicts.
4. Work the Needs Review, Unsupported, Deferred, Accepted, Rejected, and All queues.
5. For each mapping, inspect support, V1 applicability, referenced configuration template, any explicit override, review state, warnings, and evidence separately.
6. Accept, edit and accept, reject, or defer. Frequency in approved programs is evidence, not authority.
7. Generate a preview, inspect each evidence layer, and resolve blocking issues.
8. Save a new version for significant changes. Historical versions cannot be overwritten.
9. Mark `validated_for_rnd` only after the latest run meets the R&D gate and the user acknowledges the non-production boundary.

Validation for R&D is not production approval, machine safety, collision proof, post certification, or verified Creo import compatibility.
