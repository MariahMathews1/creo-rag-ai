# Profile extraction review guide

Select only controlled documents that apply to the exact machine and controller.
Machine/operator/specification sources are generally stronger for physical
limits; controller/programming sources are stronger for command syntax; company
standards are stronger for internal program structure; purchase/configuration
records are stronger for installed options.

If multiple variants appear, identify the exact nameplate/configuration before
accepting variant-dependent values. Never combine the travel of one model with
the spindle or options of another.

For each field:

1. Inspect status, confidence components, original unit, and interpretation.
2. Open every supporting and conflicting citation.
3. Confirm document revision, controller context, option dependency, and whether
   the cited statement is normative or merely an example.
4. Accept only unchanged evidence-backed values. Use edit/manual entry with a
   note when exact-machine evidence justifies a correction.
5. Reject inapplicable evidence; defer unresolved questions; mark genuinely
   irrelevant fields not applicable.

High confidence still requires review. Low confidence usually signals missing
units, ambiguous variants/options, or weak authority. A conflict is never
resolved by automatically choosing the smaller/larger value. Operator manuals
may describe a family or optional package and are insufficient by themselves to
prove installed configuration.

After all proposals have an intentional disposition, create a draft using an
explicit basis and inspect the neutral current-versus-proposed comparison. The
draft is inactive. Approval is a later explicit action requiring confirmation
against the exact machine, controller version, options, controlled documents,
and organizational standards.
