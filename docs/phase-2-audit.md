# Phase 2 foundation audit

This audit covers the repository scaffold, backend persistence and API, parser and validators, frontend integration, test setup, and container configuration.

| Problem | Cause | Fix applied | Files changed |
| --- | --- | --- | --- |
| Required API routes did not match the generated routes. | The initial scaffold used `/machine-profiles`, `/analysis-projects`, and `/analyze`. | Established `/api/machines`, `/api/analyses`, and `/run`; added full `PUT` replacement semantics while retaining a hidden compatibility `PATCH`. | `backend/app/api/machine_profiles.py`, `backend/app/api/analysis_projects.py`, `frontend/src/api/client.ts` |
| Health response did not match the documented contract. | It returned `ok` and omitted `API` from the service name. | Health now returns `healthy` and `Creo NC Post Assistant API`. | `backend/app/main.py`, `backend/app/core/config.py` |
| Analysis status merged blocking and warning results. | The initial model exposed only `analyzed` and `needs_review`. | Added `blocked`, `review_required`, and `passed` calculation, plus an idempotent SQLite data migration for existing statuses. | `backend/app/models/entities.py`, `backend/app/api/analysis_projects.py`, `backend/app/db/migrations.py` |
| Existing SQLite databases could not receive additive model fields. | `create_all()` creates missing tables but does not alter existing ones. | Added a development compatibility migration and automatic startup execution; the rapid-Z threshold is now persisted. | `backend/app/db/migrations.py`, `backend/app/main.py`, `backend/app/models/entities.py` |
| Command normalization was inconsistent between profile input, parser output, and rules. | The API stored caller formatting and the parser collapsed leading zeros. | Commands normalize to `G00`, `G01`, `M03`, etc. at the API boundary and validator comparison boundary. | `backend/app/schemas/machine_profile.py`, `backend/app/parsers/gcode.py`, `backend/app/validators/engine.py` |
| Parser data did not expose the complete requested structure or state. | The first pass used compatibility-oriented field names and tracked only a subset of modal groups. | Added original/cleaned text, per-line errors, compact syntax support, and typed feed, spindle, tooling, coolant, spindle, offset, and compensation state. | `backend/app/parsers/gcode.py`, `backend/app/parsers/__init__.py` |
| Validation logic was monolithic and rule IDs did not match the stable contract. | All checks were private methods of one engine. | Introduced a reusable typed rule interface with metadata and the specified stable IDs; corrected work-offset timing, end detection, feed severity, and safety wording. | `backend/app/validators/engine.py` |
| Analysis responses did not carry machine-readable safety metadata. | Safety messaging existed only in UI copy. | All analysis representations and run responses now include `advisory_only` and the required safety notice. | `backend/app/schemas/analysis.py` |
| Local CORS and frontend environment defaults could disagree. | Only `localhost` was allowed and the frontend used `VITE_API_URL` instead of the required key. | Added both local hostnames and standardized on `VITE_API_BASE_URL`; updated Docker build wiring. | `.env.example`, `backend/app/core/config.py`, `frontend/src/api/client.ts`, `frontend/Dockerfile`, `docker-compose.yml` |
| Root environment configuration was not reliably discovered when Uvicorn started from `backend/`. | Pydantic resolved `.env` only against the process working directory. | Configuration now reads the root `.env` and permits a backend-local override. | `backend/app/core/config.py` |
| Results linked to source lines but could not be selected as a review interaction. | Findings used anchors only and code highlighting was severity-driven. | Findings are keyboard-accessible selectable controls; selection highlights and scrolls to the exact source line and keeps full rule details visible. | `frontend/src/pages/AnalysisResultsPage.tsx`, `frontend/src/styles.css` |
| Required sample-loading and robust API states were missing. | Samples existed only as files and some failed requests were silently ignored. | Added safe/problematic/CL sample controls plus loading, empty, invalid, running, missing-profile, and backend-unavailable states. | `frontend/src/features/analysis/samples.ts`, frontend pages, `frontend/src/api/client.ts` |
| Frontend build emitted repository artifacts and lacked a separate typecheck command. | Composite TypeScript configuration had produced compiled config and build-info files. | Removed generated artifacts and added `lint` and `typecheck` scripts that do not emit files. | `frontend/package.json`, generated files removed |
| Test coverage did not exercise the complete end-to-end contract. | Initial tests covered only the first scaffold. | Expanded parser, every deterministic rule, CRUD, statuses, reruns, persistence, selection, filtering, counts, form submission, and API failures. | `backend/tests`, `frontend/src/**/*.test.tsx` |
| Root development commands and Windows setup were incomplete. | Only per-service commands were documented. | Added `make install/dev/test/build` and equivalent manual commands, including PowerShell activation. | `Makefile`, `README.md` |

No circular imports or broken SQLAlchemy relationships were found. `MachineProfile` owns documents and analyses with explicit delete-orphan behavior; `AnalysisProject` owns findings. The application remains intentionally migration-light for the proof of concept; a production phase should replace the compatibility migration with Alembic.

Docker configuration was repaired and statically audited for service addressing, CORS, build-time browser API configuration, and persistent SQLite storage. The current development host does not provide the Docker CLI, so container startup could not be executed here; run `docker compose up --build` on a Docker-enabled host for the final runtime check.
